# design-AOB一键更新同步功能-20260523-001

## 1. 背景与目标

现有 AOB 已有两个相邻能力：

1. `aggregate-user-content`：把用户级来源聚合到 `libs/aol/canonical.aol.json`。
2. `publish-user-content`：把 canonical AOL 编译后发布到各用户级目标。

用户要求新增一个“一键更新”能力，目标是把 `libs` 与各发布目标做双向同步，支持新增、更新、删除统一收敛。

## 2. 设计范围

本设计只覆盖 AOB 用户级内容同步域，包含：

1. canonical AOL 与用户级目标目录之间的双向同步。
2. 自动发现目标与显式目标两种模式。
3. `dry_run`、过滤（engine/ide）、`include_missing` 等现有参数契约的复用。
4. 同步数据库（registry）用于“同名内容最新侧”判定。

不覆盖：

1. 新引擎 emitter 扩展。
2. 非 AOB 路径（例如 workflow installer）行为改造。

## 3. 一键更新能力定义

新增命令：`update-user-content`

语义：

1. 读取 `libs/aol/canonical.aol.json`（libs 侧快照）。
2. 对每个目标目录执行 AOC 反编译，得到目标侧 AOL 快照。
3. 先基于同步数据库判断同名内容哪边是“最新变更”。
4. 若数据库信息不足（初次同步或缺失记录），退化为“当前观测快照 + 文件时间”判定。
5. 产出一个统一的“最终 canonical AOL”，并写回 `libs/aol/canonical.aol.json`。
6. 用最终 canonical AOL 重新编译并发布到所有目标。
7. 对已托管文件执行镜像清理，删除在最终 canonical 中已不存在的文件（删除同步）。

## 4. 同步模型

### 4.1 逻辑条目

将 AOL payload 扁平化为逻辑条目（`logical_key`），示例：

1. `title::__root`
2. `project_instruction::__root`
3. `instructions::<sha256>`
4. `agents::<id>`
5. `skills::<name>`
6. `rules::<id>`
7. `commands::<id>`
8. `hooks::<relative_path>`
9. `extra_assets::<relative_path>`
10. `mcp_servers::<server_name>`
11. `settings::__root`
12. `policies::__root`
13. `engine_native::<engine_id>`

说明：

1. 逻辑条目用于跨引擎语法对齐，避免直接按文件路径硬比。
2. `instructions` 采用内容哈希键，等价视作集合语义。

### 4.2 Side 定义

每个参与方是一个 side：

1. `libs`：canonical AOL。
2. `target:<target_label>`：每个发布目标反编译后的 AOL。

每个 side 在本轮有两类状态：

1. `exists=true + value_hash`
2. `exists=false`（表示该 side 删除了该条目）

### 4.3 最新判定（两段式）

优先级一：数据库判定

1. 对每个 `logical_key + side_id`，维护 `value_hash`、`exists`、`changed_at_epoch`。
2. 本轮如果发现与上一轮记录不同，则更新该 side 的 `changed_at_epoch`。
3. 在同一个 `logical_key` 上，`changed_at_epoch` 最大的 side 作为胜出方。

优先级二：回退判定

仅当数据库无法提供有效比较时启用：

1. 使用 side 的观测时间（canonical 文件 mtime、目标目录内容 mtime）作为回退时间戳。
2. 仍按最大时间戳决策。

### 4.4 新增、更新、删除判定

1. 新增：胜出 side 为 `exists=true`，且其他 side 不存在该 key。
2. 更新：多个 side 都存在该 key，但胜出 side 的 hash 不同。
3. 删除：胜出 side 为 `exists=false`，最终 canonical 移除该 key，并同步删除到目标。

## 5. 数据存储设计

在 `database/items_registry.sqlite3` 中新增两张表：

1. `user_content_sync_registry`
2. `user_content_sync_target_files`

### 5.1 user_content_sync_registry

字段：

1. `logical_key TEXT NOT NULL`
2. `side_id TEXT NOT NULL`
3. `exists_flag INTEGER NOT NULL`
4. `value_hash TEXT NOT NULL`
5. `changed_at_epoch REAL NOT NULL`
6. `updated_at_epoch REAL NOT NULL`
7. `PRIMARY KEY (logical_key, side_id)`

用途：

1. 存储同名逻辑条目的变更时间基线。
2. 支持“数据库优先”比较。

### 5.2 user_content_sync_target_files

字段：

1. `target_label TEXT NOT NULL`
2. `layout TEXT NOT NULL`
3. `relative_path TEXT NOT NULL`
4. `updated_at_epoch REAL NOT NULL`
5. `PRIMARY KEY (target_label, layout, relative_path)`

用途：

1. 记录上次托管文件清单。
2. 新一轮发布时支持差量删除（镜像清理）。

## 6. 发布阶段删除同步策略

### 6.1 托管文件集合

每个目标在发布时都会有一个“本轮编译输出托管集合”：

1. `structured_root`：编译输出目录内全部文件 + 受控根文件（如 `CLAUDE.md`、`GEMINI.md`、`AGENTS.md`、`opencode.json`）。
2. `prompt_root`：仅 `.prompt.md` 和 `.instructions.md` 投影文件。

### 6.2 删除规则

1. 从数据库读取该目标上轮托管集合。
2. `上轮托管 - 本轮托管` 为删除候选。
3. 仅删除候选路径，且不扫描删除非托管文件。

这样可避免误删用户私有文件。

## 7. CLI 与工具层接口设计

### 7.1 library 子命令

新增：

`python scripts/aob_tools/library.py update-user-content [options]`

参数：

1. `--target-path`（可重复）
2. `--home-dir`
3. `--engine`（可重复）
4. `--ide`（可重复）
5. `--include-missing`
6. `--dry-run`
7. `--skip-items-sync`

### 7.2 tools API

新增：

1. `run_aob_update_user_content(...)`
2. `aob_update_user_content(...)`

并接入 `AOB统一业务事务`：

`mode=update_user_content`

## 8. 返回结果设计

新增结果对象关键字段：

1. `status`：`ok`/`error`
2. `dry_run`
3. `target_count`
4. `registry_summary`：数据库命中、回退次数
5. `decision_summary`：新增、更新、删除决策计数
6. `canonical_write`：canonical 写入状态
7. `publish_summary`：新增/更新/删除计数
8. `items_sync`
9. `warnings`
10. `errors`

## 9. 测试设计

新增测试文件：`tests/test_aob_user_content_update.py`

至少覆盖：

1. libs 新内容应同步到全部目标。
2. 单目标较新内容应回流到 libs，再同步到全部目标。
3. 删除应能通过托管清单同步删除到其他目标。
4. 缺失 canonical 时可通过目标侧构建并生成 canonical（或给出明确错误）。
5. `dry_run` 不落盘、不改数据库。

## 10. 风险与约束

1. 首次运行数据库为空时，判定依赖回退时间戳，精度有限。
2. 不同引擎语法映射可能导致部分字段只能 `partial` 对齐。
3. 删除同步只对“托管文件”生效，避免误删非托管内容。
4. 一键更新默认会触发目标写入，建议先 `dry_run`。
