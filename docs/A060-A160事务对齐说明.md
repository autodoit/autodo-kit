# A060-A160事务对齐说明

## 1. 适用范围

本说明用于统一 autodo-kit 在 A060-A160 这段事务链上的解释口径，避免以下三层长期漂移：

1. 宿主主链中的节点编号与节点名称。
2. autodo-kit 中的官方 affair 名称与模块路径。
3. 宿主侧编号补位智能体、工具侧事务说明与手册快照。

本说明只负责对齐当前有效口径，不承担历史变更记录职责。

## 2. 三层结构

当前应按三层结构理解 A060-A160：

1. 主链节点层：宿主通过 `affair_entry_registry.json` 或等价注册表决定哪个节点编码映射到哪个官方 affair。
2. 官方事务层：autodo-kit 中各 `autodokit.affairs.<事务名>.affair.execute` 才是默认执行入口。
3. 补位解释层：宿主侧编号事务智能体只负责单节点补位、说明和排障，不是 autodo-kit 的默认执行入口。

因此，阅读 autodo-kit 文档时，应优先确认“宿主把哪个节点映射到哪个官方 affair”，再决定是否需要看补位智能体说明。

## 4. 当前必须区分的 legacy 事务

### 4.1 综述预处理

`autodokit.affairs.综述预处理.affair.execute` 仍然存在，但它现在只应被解释为：

1. 历史链路回放事务。
2. 局部 parse asset 补位事务。
3. 兼容排障入口。

它不再是当前主链中 A060 的官方映射。

### 4.2 命名仍保留旧模块名的事务

以下事务需要特别注意“模块名”和“当前节点职责”并不完全同名：

1. `非综述候选视图构建`：当前宿主口径通常把它作为 A080 普通文献泛读来使用。
2. `文献研读与正式知识回写`：当前宿主口径通常把它作为 A100 文献批判性研读来使用。
3. `创新点池构建`：当前宿主口径通常把它作为 A140 创新点凝练来使用。

阅读手册或 API 时，必须以“当前宿主映射”和“当前事务真实输出”为准，而不是只看模块中文名做推断。

## 5. 推荐的柔性简并视图

### 5.1 综述超节点

推荐把 `A065 + A070` 理解为当前 A070 外部节点内部的两个连续阶段：

1. A065：reference preprocessing。
2. A070：review synthesis。
A060 保持独立，因为它承担综述候选视图与共享预备资产入口；A075 也已恢复为独立桥接节点，不再属于综述超节点内部阶段。

### 5.2 普通阅读超节点

推荐把 `A080 + A095` 理解为普通阅读主段：

1. A080：预处理入口。
2. A095：粗读主算、批次汇总与 A100 推进。

### 5.3 深读双节点

`A100` 当前已吸收原 A105，作为深读与知识回写一体化节点：

1. A100 解决“资产是否已具备深读条件”。
2. A100 在同一外部节点内完成标准笔记与知识回写。

### 5.4 分析交付集群

`A110-A160` 更适合被理解为知识收束与交付分析集群：

1. A110/A120 负责收束材料。
2. A130 是占位但可运行的知识框架节点。
3. A140/A150 形成创新分析子链。
4. A160 是最终交付端口。

## 6. 阅读 autodo-kit 文档时的优先顺序

1. 先看本说明，确认节点与官方 affair 的映射关系。
2. 再看 [AOK预置事务手册](AOK预置事务手册.md)，理解单个 affair 的输入、输出与参数。
3. 再看 [API手册](API手册.md)，确认公开契约、状态字段和 CLI/运行时入口。
4. 若需要理解宿主如何把这些 affair 组织成具体主链，再看宿主侧的工程设计与用户手册。
